FRAME

Inhabit

FRAME is already a place. The native experience is not “using software.” It is inhabiting a live graph of meaningful things, with attention as the only hard UI primitive.

First thing you see

Not a desktop. Not a home screen.

You see presence: the world as it currently concerns you.

That is a continuous projection of FRAMEs in your ActiveContext — you, what you are inside, what is pressing on you, what is offering itself. It updates as the graph updates. Nothing “launches.” The world is already on.

If that still feels like a feed, that is residual metaphor. Structurally it is closer to standing in a room that rearranges itself when reality changes.

What replaces apps

Nothing replaces apps as a category. Apps were containers for disconnected worlds.

In FRAME, a “thing you can do” is either:

  1. a FRAME you are attending, or
  2. a recommendation over FRAMEs you are attending (propose an Intent).

Gauge Labs is not an app. It is a FRAME you enter. Diagnostics is not an app. It is a capability-bearing surface of that FRAME, revealed because you are there.

The replacement for apps is situated affordance: what this FRAME offers here, now, to you.

What replaces folders

Folders were a filing fiction: put object X into container Y so humans can find it later.

FRAME already has structure: containment, association, membership, location, ownership — as live relationships, not directories.

You do not file a project under Work. You relate to it. Finding it later is not browsing a tree; it is re-entering a neighborhood of the graph you already belong to.

If something looks like a folder, it is usually a containment projection — a view of Contains, not a filesystem.

What “opening” means

Opening is the wrong word. It implies a sealed package becoming a window.

Native verb: enter.

Entering a FRAME means:

  • it becomes ActiveContext (or nested inside it)
  • projection density increases
  • recommendations recompute for this locus
  • the previous locus is not closed; it is beneath / around / behind attention

You do not open Car. You enter Car. The car becomes the world for a while. Ascending does not “close the car app”; it releases that FRAME as the center of attention.

That interaction is hard to fake in old OSes because they do not have one shared world object.

What navigation means

Navigation is moving attention through the graph.

Not:

  • go to a URL
  • open a screen
  • switch an app

But:

  • attend this FRAME
  • enter deeper
  • follow a relation to another FRAME
  • widen (see more of the ambient set)
  • recenter on yourself

Space is semantic, not geometric — though geometry can be one projection of it. You are never “on a page.” You are at a locus in the graph.

What stays persistent

While projections flicker, three things persist:

  1. You as the inhabitant — the continuous subject of attention (without needing to lecture Identity).
  2. The live world — the same graph keeps revising under you.
  3. Your locus — where attention is currently centered, and the path of enters that got you there.

Everything else is projection. Windows were persistent chrome pretending to be place. Here, place is the FRAME you are in; chrome is optional and non-native.

Focus

Focus is not “which window is frontmost.”

Focus is: which FRAME is currently the center of projection.

One focus at a time is enough for a human. Multi-focus is possible as split attention, but it is the same primitive twice — not a window manager.

Pointer, voice, gaze, tap — those are modalities for Attend. Attend is fundamental. Click is not.

Context

Context is not a settings panel. It is the ambient filter on what may appear and what may be offered.

You entered Gauge Labs → vehicle tools flood the stream.
You are walking → city / place FRAMEs thicken.
You are with Ted → shared project pressure rises.

Context changes what the world presents, not which app is running.

Knowing where you are is knowing:

  • who you are attending as yourself
  • which FRAME is the center
  • what ambient Context is active

That can be as thin as a name + a few pressing neighbors. It does not need a breadcrumb bar. If you show a path, it is the enter-path, not a folder path.

How different beings appear

They all appear the same way: as FRAMEs entering presence.

Being What you notice first What differs
Person name, shared pressure, invitation to act together social / shared Intents
AI suggestion, explanation, draft Intent speaks in recommendations and why
Organization membership, updates, available places inside it scale of containment
Project status, waiting decisions, collaborators work-shaped recommendations
City place you are in, services, nearby FRAMEs spatial Context
Vehicle health, distance, diagnostic offers body-like status + act

Same verbs: Attend, Enter, Act, Ask why, Watch change.

Different content. Same system. That sameness is the discovery. Old OSes needed different apps because they had no shared object model. FRAME does — so kind is costume; interaction is constant.

Smallest interaction vocabulary

Strip inheritance. What must exist?

Verb Meaning Fundamental?
Attend Make this FRAME the focus Yes
Enter Make this FRAME the world (deepen Context) Yes
Widen / Ascend Release depth; return attention outward along enter-path Yes (pair of Enter)
Act Accept / refuse / edit a recommendation → Intent Yes
Why Demand explanation / provenance for what you see or are offered Yes — FRAME-native
Watch Stay and receive revision of this locus (history as lived time) Yes — FRAME-native
Suppose Temporarily inhabit a non-authoritative branch (simulate) Yes — FRAME-native
Find Pull distant FRAMEs into attention by query Useful, not sacred
Click / Back / Home / Search / Desktop Inherited modalities or places Not fundamental

Back is only fundamental if you treat Enter as a stack. Graph-natively it is Ascend / return along path, not browser Back.

Home is only fundamental as recenter on the inhabitant’s ambient presence — not a desktop.

Search is a power tool for sparse graphs. Day-to-day inhabitation is presence + follow + recommend, not query boxes.

Desktop is not fundamental. It is one Perspective for architects who need to see too much at once. Living does not require it.

Interactions that could not exist elsewhere

These are not decorations. They fall out of one live graph + projection + intent:

  1. Enter until the object becomes the universe — then scrub its history and watch the world you are inside change shape.
  2. Why? on anything — not a help page; the object’s own causal story.
  3. Suppose — stand in a ghost world that shares ontology with reality but cannot commit until you Act for real.
  4. Same object, shift Perspective without leaving — architect density vs living density vs vehicle density; you did not switch apps; the locus stayed, the projection changed.
  5. Presence stream — the OS continuously projects what matters; you do not open tools to check if the world moved.
  6. Act from recommendation — the primary verb surface is “the world proposes; you authorize,” not “hunt a menu in an application.”

If a design cannot express those without bolting on a special app, it is still an old OS wearing FRAME vocabulary.

When it still resembles old OSes

Resemblance will appear when humans need:

  • lists (working memory is linear)
  • names (we speak)
  • confirmation (Act has consequence)
  • a way back (attention has a path)

Those are human constraints, not Windows constraints.

Danger: dressing those necessities as Dock, Settings App, Files, Notifications Center. That recreates the old OS because designers reach for familiar chrome instead of Attend / Enter / Act / Why / Watch / Suppose.

If your “FRAME OS” has a home grid of icons, you have failed the discovery. You rebuilt application launch.

If your “FRAME OS” has a person, a car, a city, and a project all reachable by the same six verbs, and entering any of them can become the whole world, you have found something that only FRAME can be.
